# 会话失效处理

## 背景

BWiki 对失效的 cookie 不报错，而是把请求当匿名访客处理，`userinfo.name` 变成调用方的出口 IP：

- 读操作照常返回公开内容，无异常提示；
- 写操作照常成功，但页面署名是 IP 而不是用户。

成功响应里没有任何字段提示身份已变。

## 机制

| 阶段 | 机制 | 时机 |
|---|---|---|
| 启动 | `bwiki/sessionGate.ts` 校验已存会话 | 服务开始前，失败即退出 |
| 运行中 | `bwiki/liveness.ts` 查 `meta=userinfo` | 每次写操作前 |

判定依据：`userinfo.name` 是否为纯数字 UID（`/^\d{5,}$/`）。BWiki 不使用常规 MediaWiki 账号，`id` 恒为 0、`anon` 不可靠，只有 name 是否为数字可信。

## 行为

| 情况 | 行为 |
|---|---|
| 会话有效 | 放行 |
| 会话失效 | 写操作被拒，返回 `authentication` 错误，随后断开连接 |
| 会话已判定失效 | 后续写操作直接拒绝，不再探测 |
| 传输失败（wiki 不可达） | 返回 `upstream_failure` 错误，连接保持，不计为登出 |
| 读操作 | 不做身份校验，始终放行 |
| 任一 wiki 判定失效 | 对全部 wiki 生效（共用一份会话） |

断连顺序：先等待 250ms 让解释性响应写出，再关闭 transport，150ms 后以退出码 1 结束进程。
